### Description

Two related mutation bugs found in `langchain_core/messages/utils.py` where caller-provided messages are silently modified as side effects.

### Bug 1: `merge_message_runs` destroys original `response_metadata`

`_msg_to_chunk()` creates chunks via `chunk_cls(**message.model_dump(...))`. Pydantic v2's `model_dump()` returns shallow references for dict fields -- the chunk's `response_metadata` is the same object as the original message's. Calling `.clear()` on it silently wiped the caller's metadata.

**Fix:** Replaced `.clear()` with `= {}` (creating a new empty dict instead of mutating the shared one).

### Bug 2: `convert_to_openai_messages` mutates caller's `message.content`

When a file-type content block has no `filename`, the code injected `"LC_AUTOGENERATED"` via `block["file"]["filename"] = ...`. Since `block` is a direct reference into the caller's `message.content`, this mutated the original message.

**Fix:** Shallow-copy `block` and `block["file"]` before mutating, so the original content stays untouched.

### From PR #39000
PR #39000: fix: preserve conversation history when summary generation fails
## Problem

When the summary model call fails (e.g. 429 rate limit, timeout), `SummarizationMiddleware` **permanently destroys the entire conversation history**:

1. `_create_summary` catches the exception and returns `"Error generating summary: ..."` as if it were a valid summary
2. `before_model` proceeds to emit `RemoveMessage(id=REMOVE_ALL_MESSAGES)`
3. The conversation is replaced with the error text

This is the worst possible failure mode: the system destroys data precisely when it's under stress.

## Fix

- `_create_summary` / `_acreate_summary`: return `None` on exception (with a logged warning) instead of error text
- `before_model` / `abefore_model`: check for `None` and return `None` (no state update), preserving messages for the next retry

The removal and replacement are now atomic: you only delete old messages if you successfully produced a summary.

## Changes

- `libs/langchain_v1/langchain/agents/middleware/summarization.py`

## Testing

The reproduction from #38867 now returns `None` from `before_model` (no state update) instead of `RemoveMessage(REMOVE_ALL_MESSAGES)` with error text. The next cycle retries summarization without data loss.

## Background

When integrating OpenAI-compatible models that expose reasoning output, such as DeepSeek / GLM / Qwen, providers often return `reasoning_content` or `reasoning` in either normal responses or streaming deltas to carry the model's reasoning text.

However, `langchain-openai` does not currently preserve these fields reliably when converting OpenAI-style responses into LangChain message objects. As a result:

- The provider returns reasoning content, but the application layer cannot read it from `AIMessage` / `AIMessageChunk`
- The frontend cannot distinguish between "answer content" and "reasoning content"
- Application code often has to wrap or subclass the model implementation just to restore this capability

This is the core issue described in [#38764](https://github.com/langchain-ai/langchain/issues/38764).

    "reasoning_content": "The"
  },
  "finish_reason": null,
